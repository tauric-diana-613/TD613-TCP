## 9. Validation architecture · “CI confirms; CI does not discover”

The A15 twenty-one-hour workflow loop must not recur.

### 9.1 Frozen-candidate law

Before a Ready event:

- assemble the complete mutation off-PR or in Draft;
- run syntax, static, and stage-local rehearsals;
- freeze the candidate head;
- prohibit source changes during the final browser packet;
- pin one PR, one branch, one head SHA, one run ID;
- quarantine any parallel commit before accepting it.

### 9.2 Report-all static law

Grouped contracts must:

- execute every member;
- preserve separate stdout/stderr;
- emit one manifest naming every failure;
- fail only after reporting the full set.

No stage should require one CI run per deterministic assertion.

### 9.3 Stage-addressable browser preflights

Every previously observed high-risk seam becomes an early bounded preflight before the complete journey.

Initial A16 risk registry includes:

- replaced controls during recompilation;
- route-control/surface disagreement;
- case/local-pointer/profile settlement;
- present-state versus temporal-stability admission;
- canonical field remount;
- canonical Play restoration;
- explicit tutorial + motion owner binding;
- reduced-motion mobile WebKit multi-control gestures;
- Firefox phase-trace completion;
- cross-tab lock and close/reopen settlement.

Preflights must:

- observe Chromium, Firefox, and WebKit;
- avoid fail-fast across engines;
- use internal budgets shorter than the outer shell ceiling;
- preserve a manifest and diagnostic packet on every hold;
- distinguish product failure, observer failure, timeout architecture, and opaque provider state.

### 9.4 Final cross-engine seal

The long complete journey is confirmation only.

It may run only after:

```text
report-all static = green
all registered risk preflights = green
local/stage rehearsal = green
candidate head = frozen
PR Ready gesture = explicit and singular
```

No duplicate witness PR, repeated Draft/Ready cycling, fake source nudge, or overlapping run is permitted merely to awaken CI.

### 9.5 Observer constitution

Observers must:

- use real visible gestures;
- reacquire replaced connected controls when necessary;
- observe current state without demanding an event that occurred before attachment;
- preserve the distinction between direct present-state admission and temporal observation;
- never repair the product by injecting state;
- never become the hidden action owner;
- emit exact field, attempt, posture, owner, and timeout diagnostics.
