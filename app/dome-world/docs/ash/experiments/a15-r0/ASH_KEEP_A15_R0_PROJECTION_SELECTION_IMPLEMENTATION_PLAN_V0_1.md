## 0. Opening determination

The A15 production body passed technical closure and failed operator acceptance.

That distinction governs this plan:

```text
technical closure ≠ product acceptance
scripted traversal ≠ usable participation
constitutional preservation ≠ pedagogical inheritance
visible explanation ≠ environmental pedagogy
```

The current interface remains a valid witness of the tested A15 implementation. It does not remain the presumptively accepted product body.

A16 shall not begin by auditing or extending a surface the operator has rejected. The next admissible action is a bounded projection-selection assay that holds the Ash kernel constant while testing whether a smaller visible body can carry one complete governed act.

This plan does not authorize a full UI rescue, a canonical Holonomy Loom, Golden Egg implementation, production cutover, mass eviction, route mutation, or release.


### R0.1 — Fixed-kernel assay harness

Implement a preview-only harness that:

- creates or loads one deterministic synthetic case;
- exposes a narrow adapter to existing Ash domain owners;
- records every projection action as an observable event;
- prevents projections from mutating release, destination, export, or closure authority;
- emits identical substrate receipts regardless of projection;
- supports clean reset without deleting governed production state.

**Exit:** all three projections can be run against the same fixture and transition sequence.

### R0.2 — P1 Minimal Ash

Build one calm task-first projection with no inherited whole-instrument overlay.

Required visible scenes:

1. **Bring** — choose a synthetic source/reference posture.
2. **Connect** — form one visible Case Map relation.
3. **Compare** — inspect one bounded route comparison.
4. **Return** — preserve, state missingness, and return.

Constraints:

- no primary TD613 terminology before consequence;
- no permanent channel legend;
- no omnipresent Flow-Core animation;
- no command-menu dependency;
- no competing navigation listener;
- no more than one primary action per scene;
- technical inspection hidden until requested;
- Rest and Return always available after the first governed action.

**Exit:** the shared task can be completed in P1 with exact receipts and no widened authority.

### R0.3 — P2 Proto-Loom

Build one bounded route-comparison projection.

The Proto-Loom is not the Golden Egg and may not claim tomography, holonomy, curvature, semantic non-leakage, external DLP, or complete route witness.

It may display:

```text
one controlled reference
→ route A observation
→ return
→ route B observation
→ return
→ bounded signed residue
→ missingness / alternatives / claim ceiling
```

It must answer, without prior doctrine:

- What entered?
- Which routes differed?
- What stayed local?
- What returned?
- What changed?
- What remains unknown?

The Loom must consume route and receipt evidence. It may not take custody or command Ash.

**Exit:** the shared task can be completed in P2 with exact receipts and no widened authority.

### R0.4 — Comparative observation

Run `P0`, `P1`, and `P2` under one declared protocol.

Record observable interface facts only:

- visible-control count before first meaningful action;
- lawful-control ratio;
- dead-affordance count;
- control-to-consequence distance;
- unexplained seam count;
- consequential boundary-crossing count;
- technical terms encountered before experience;
- backtracking;
- recovery attempts and outcomes;
- Rest success;
- Return success;
- help requests;
- abandonment;
- ability to identify what changed, what stayed local, and what remains unknown.

Do not infer cognition, intelligence, mastery, identity, emotion, psychological safety, authorship, intent, consent, or moral character.

**Exit:** each projection has a complete observation receipt with missingness and alternatives.

### R0.5 — Falsification and disposal

Each candidate must name reversal conditions before selection.

Reject a projection if it:

- requires another navigation owner;
- requires permanent explanatory furniture;
- depends on the failed whole-instrument animation;
- cannot be removed cleanly;
- mutates governed state outside the adapter;
- obscures source/reference distinction;
- converts residue into attribution;
- hides missingness;
- makes Rest or Return decorative;
- needs prior TD613 fluency for the shared task;
- creates a new serverless function;
- requires production deployment to evaluate;
- produces a larger interface than the task it serves.

**Exit:** failed candidates are deletable without data migration.

### R0.6 — Human selection gate

Permitted outcomes:

```text
MINIMAL_ASH_SELECTED
PROTO_LOOM_SELECTED
SELECTIVE_RESCUE_SELECTED
NO_PROJECTION_ACCEPTED
```

The selection receipt must include:

- operator rationale;
- unresolved risks;
- implementation boundary;
- whether A16 scope must be rewritten;
- explicit confirmation that no production action occurred.

**Exit:** one operator-confirmed direction or an explicit hold.
