## Question

Can the existing three-engine A15-R0 browser calibration directly observe the Holonomy Loom preview's default deterministic interaction and test whether a unique raw-draft canary appears in any browser request after the operator begins interacting with the draft?

## Witness

The descendant adds `scripts/holonomy-loom-browser-egress-witness.mjs` and invokes it from the existing per-engine A15-R0 calibration probe. No workflow topology, production surface, provider route, timeout, deployment path, or product release path is added.

For each Chromium / Firefox / WebKit episode the witness:

1. loads the child-legible Loom preview;
2. confirms consequence-first copy and `Show me why` closed by default;
3. opens Protection rules through an explicit visible user gesture;
4. places a unique per-engine canary in the draft plus an exact protected term and exact journey marker;
5. runs the visible `CHECK THIS MESSAGE` control;
6. requires RED, raw-copy refusal, safer-copy availability, and the declared journey relation;
7. requires `Show me why` to remain optional after consequence;
8. observes every browser request after draft interaction begins;
9. stores only minimized request descriptors — method, origin, pathname, query-present, post-data-present, and booleans indicating canary presence;
10. requires zero observed canary egress, zero external request, and zero mutation request during the default interaction;
11. clears explicit protected/journey rules, reruns the visible control, and requires bounded GREEN semantics plus provenance abstention;
12. again requires zero observed canary egress.

The raw canary itself is never written into the witness receipt.
