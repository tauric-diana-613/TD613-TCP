## Question

Can a genuinely portable Holonomy Loom Pocket perform a bounded pre-ingress local check and create a born-minimized portable AIA packet without a server, model, network request, persistence layer, or parallel hand-maintained Loom ontology?

## Construction target

The Pocket is a single portable HTML artifact generated from the repository's canonical Holonomy Loom policy.

The generated artifact must:

1. load no remote resource;
2. require no API route, Gemini key, ChatGPT connection, server, or model;
3. persist no draft, protected term, finding, or local binding automatically;
4. inspect the raw draft locally only;
5. expose child-legible `SEE → CHECK → UNDERSTAND → REST` interaction before technical drawers;
6. relock its copy/export doors whenever draft or protection input changes;
7. refuse copy/export while any canonical `REMOVE` finding remains unresolved;
8. permit only the canonical LOCAL_POCKET route boundary in its born-minimized portable AIA packet;
9. keep policy/source-state digests, receipt text, raw matches, spans, user-protected values, and route-history prose out of the portable packet;
10. derive its embedded rule/action/evidence/category/why vocabulary from the canonical Loom policy at build time rather than maintaining a second policy table by hand.

## Deliberate split

```text
RAW DRAFT
  ↓ local-only inspection
LOCAL FINDINGS
  ↓ operator resolves / generalizes
LOCAL POCKET GATE
  ↓ only after explicit export gesture
BORN-MINIMIZED PORTABLE AIA PAYLOAD
```

The Pocket's local inspection state is not itself portable payload.

```text
LOCAL_FINDING_STATE != PORTABLE_PACKET
LOCAL_BINDING != PORTABLE_PACKET
CHECKED_DRAFT != RELEASE_AUTHORITY
GREEN != ZERO_PRIVACY_RISK
```

## Canonical-token rule

The export packet may contain only values admitted by `compilePortableAiaProjection()` / `auditPortablePayloadVocabulary()` for route `LOCAL_POCKET`.

No caller-supplied receipt ID, host prose, journey label, source label, finding explanation, raw match, selected text, prompt transcript, digest, or arbitrary action string may become portable packet content.

## Network / persistence falsifiers

Any of the following fails the chamber:

- a default `fetch`, XHR, WebSocket, EventSource, beacon, form submit, worker, frame, remote stylesheet/script/font/image, or other network-capable dependency;
- any localStorage, sessionStorage, IndexedDB, Cache API, service worker, cookie, or automatic file persistence of draft/protected material;
- any hidden model/provider call;
- any API key requirement;
- any external URL embedded as an operational dependency.

CSP must default-deny and explicitly deny connections.

## Copy/export falsifiers

Any of the following fails the chamber:

- copy/export enabled before an explicit local check;
- changed draft/protection state does not relock the gate;
- a canonical `REMOVE` finding can leave unresolved;
- a portable packet contains raw draft text, a raw match, a user-protected value, a span, a digest, receipt text, arbitrary prose, or a route label outside the canonical boundary tokens;
- a generated packet claims Loom release authority;
- an exported packet claims human closure is unnecessary.

## Pedagogue hypothesis

A first-time human can encounter the Pocket through:

```text
SEE       = paste / declare
CHECK     = run the local Loom
UNDERSTAND = consequence + simple finding cards
REST      = nap/rest state that preserves the last result without new processing
```

Technical rule IDs and exact packet JSON may remain behind optional drawers.

The browser assay may establish control visibility and interaction reachability. It cannot by itself establish human comprehension.

## Aperture claim ceiling

A successful local browser witness may establish only that the declared artifact performed the tested local behaviors under tested inputs while the browser observer saw no admitted network/persistence activity.

It does not establish universal privacy, browser/platform secrecy, OS clipboard secrecy, upstream ChatGPT secrecy, or absence of channels outside the tested artifact/browser contract.

## Atlas hypothesis

For the Pocket-generated LOCAL_POCKET projection:

- `POLICY_ONLY` receiver remains in the same policy equivalence class as the other route projections for the same rule;
- `BOUNDARY_AWARE` receiver retains the LOCAL_POCKET boundary distinction using canonical boundary tokens only;
- the Pocket must not need route-label prose or host strings in the portable payload to retain that distinction.
