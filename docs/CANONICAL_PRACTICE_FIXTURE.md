# Canonical Practice Fixture / Calibration Phantom

## Purpose

A complicated Dome-World workspace may declare a **Canonical Practice Fixture** when an operator needs a harmless way to learn or verify the real route before consequential material enters it.

Human-facing language should prefer **Practice case**, **Practice inhabitant**, or another product-native phrase. **Calibration phantom** is the research/test term for the same object when the fixture is used as known ground truth for route reconstruction.

A practice fixture is not a mock app, not a detached demo world, not a fabricated evidentiary record, and not an authorization shortcut.

Its defining law is:

```text
fiction may exercise reality
!= fiction becomes evidence
!= fiction gains consequence authority
```

The practice payload enters the same declared route as consequential material. It may exercise real validators, state transitions, receipts, custody mechanics, rest, return, and exits. The fixture remains manifestly fictional and authority-closed throughout.

## Admission criteria

A surface should opt in only when all of the following can be true at once:

1. **Container before content** — the workspace can create or reveal a harmless working container before consequential records arrive.
2. **Route before jargon** — the operator can see the major consequence-bearing route in plain language before learning internal ontology.
3. **No invented evidence** — loading the fixture changes labels or fictional inputs only. It does not fabricate source records, receipts, source bytes, claims, or retrieved evidence.
4. **No automatic retrieval** — a practice fixture may permit a read-only source call only after a separate explicit operator gesture.
5. **No automatic custody write** — saving or encrypting a practice object requires a separate explicit operator gesture.
6. **No domain mutation** — a practice fixture may not create a real CRM person, send a message, alter a campaign database, release a governed object, or perform another consequential domain mutation.
7. **Practice authority survives the route** — evidence-claim authority, consequence authority, automatic release, automatic redesign, and automatic Ash action remain closed.
8. **Same runtime route** — the practice case uses the real route. A product must not create a second simplified demo route and then treat that route as evidence that production is understandable or safe.
9. **Rest and exit remain real** — practice mode does not trap the operator in a tutorial state.
10. **Human closure remains human** — successful traversal never promotes itself into deployment, release, or compliance authority.

If a surface cannot satisfy these conditions, it should not claim a canonical practice fixture merely because a toy sample would be convenient.

## Load law

Fixture loading is intentionally stricter than later practice traversal.

The canonical load observation is a zero-effect delta across:

```text
evidence records
retrieval requests
retrieval receipts
practice custody writes
domain mutations
authority grants
```

A product may fill a fictional title, fictional principal name, fictional queue, harmless labels, or another bounded practice payload. The load gesture itself must not search, save, encrypt, synchronize, create evidence, or grant authority.

This distinction lets CI test a very strong negative promise: **the sample exists without acting on the world.**

## Traversal law

After load, an operator may deliberately exercise admitted parts of the real route.

A fixture may declare:

- `operator_read_only_retrieval_allowed = true` when a deliberate source call is useful and safe;
- `practice_custody_write_allowed = true` when the real route includes a reversible practice-scoped save or encrypted custody operation.

Both require an explicit human gesture. Neither grants evidentiary authority. Domain mutations, authority grants, and evidentiary claims remain forbidden.

The distinction is important: forbidding every write would often force a fake route. A reversible, explicitly gestured practice-custody write can be more scientifically honest than a demo button that merely pretends the write occurred.

## AIA posture

A Canonical Practice Fixture may be evaluated through the generic AIA surface binding, but it must not be treated as a fabricated decoy.

```text
fabricated_decoy = false
manifestly_fictional = true
route_inference = forbidden
authority_crossing = false
human_closure = required
```

Authorized operators may receive child-legible **NOW / WHY / EXACT** explanations. Unauthorized routes continue to receive minimum-disclosure, non-authoritative refusal. The practice fixture does not justify reciprocal disclosure of the system's internal topology.

## Pedagogue posture

Pedagogue grades the practice contract before a product treats it as a canonical teaching route. The Design Gate runner accepts both design fixtures and canonical practice fixtures.

A practice review verifies that:

- fiction is explicit;
- no evidence is embedded in the payload;
- the expected route is declared;
- a separate demo route is forbidden;
- automatic retrieval is forbidden;
- domain/evidence/consequence authority remains closed;
- AIA authority does not cross the binding;
- route memory remains explicit;
- geometric claims stay held;
- human closure remains required.

Example:

```bash
node scripts/run-pedagogue-design-gate.mjs tests/fixtures/pedagogue/giving-bikini-bottom-practice.json
```

### Release-smoke contract

`tests/pedagogue-practice-fixture.test.mjs` is the focused release-smoke contract for the product-neutral practice-fixture compiler. It deliberately remains small enough to run inside the one-shot Vercel release membrane while proving the boundaries that matter at release time:

- manifest fiction remains authority-closed;
- fixture load is zero-effect;
- deliberately admitted read-only retrieval and reversible practice custody still require an explicit operator gesture;
- observed authority cannot widen beyond the fixture declaration;
- same-endpoint route divergence remains measurable without becoming a transport, curvature, or geometric-holonomy claim.

The broader `tests/pedagogue-design-gate.test.mjs` suite remains the deeper architecture/integration witness. A `practice` Vercel release runs both contracts before deployment, then verifies exact deployed bytes and performs one bounded production Chromium practice observation. Live Ash production probes remain reserved for `full` scope.

Because the current production proving surface for the canonical practice fixture is Giving, both `giving` and `practice` releases materialize `app/giving/history/release-source.json` with the **authorized source-packet commit** before deployment. The production practice witness refuses to trust the Giving surface when that receipt names a different packet, even if the visible application bytes otherwise match. This receipt is release provenance only: it grants no Giving evidentiary authority, performs no donor retrieval, and does not convert practice content into evidence.

## Route reconstruction / tomography

A calibration phantom supplies known route ground truth.

For expected route `R_e` and observed route `R_o`, TD613 currently reuses the bounded Pedagogue route-memory comparison:

```text
D_route = round(1000 * d_L(R_e, R_o) / max(|R_e|, |R_o|, 1))
```

The practice traversal report exposes:

```text
route_reconstruction_error_millipoints = D_route
```

This is a discrete engineering surrogate for reconstruction error. It can distinguish:

```text
same visible endpoint
!= same route history
```

It is **not** a claim of an affine connection, parallel transport, intrinsic curvature, a curvature tensor, or geometric holonomy.

Those claims remain held until TD613 declares a transport law and performs an actual path-composition experiment.

## Ash / Loom recovery law

The practice-fixture machinery may be used **about** Ash before it is installed **inside** live Ash.

The first Ash/Loom calibration phantom belongs in research/test custody only. Its job is to test whether a known path can be reconstructed and whether a deliberately altered path leaves measurable route residue.

```text
Ash runtime binding = opt-in later
Proto-Loom implementation = not implied
transport law = not declared
holonomy claim = not earned
Golden Egg authority = unchanged
```

This preserves the emergency-rescue boundary established by the completed A15-R0 work while giving future tomography a known-ground-truth object.

## Product vocabulary law

Product-specific nouns stay in product fixtures.

Bikini Bottom belongs to Giving. An Ash practice capsule belongs to Ash research fixtures. Neither becomes Pedagogue ontology.

Only the product-independent mechanic enters shared core:

```text
local problem
→ isolate mechanic
→ remove product taxonomy
→ test independently
→ prove authority did not widen
→ promote the abstraction only
```
