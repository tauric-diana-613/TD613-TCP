## Minimum route recommendation

Use one returned-work drawer attached to the current Loom session. Preserve the builder and original route; do not introduce a second demo shrine.

| Gesture | Before the gesture | Visible world answer | Head consequence |
| --- | --- | --- | --- |
| Open returned work | “Bring back the task, answer and receipt you want Loom to inspect.” | Inputs are staged locally; current admitted head still shown. | None |
| Check returned work | “Check compares this return with your Loom anchor. It keeps your admitted history unchanged.” | MATCH / HOLD with concrete local reasons, declared/recomputed scope, and missing capture/source evidence. | None |
| Challenge | “Tests a captured episode; the local answer key stays here. A bounded clean result leaves ancestry unchanged.” | Bounded clean / exposure / HOLD, plus captured horizon. | None |
| Review admission candidate | Visible proposed parent, task/answer preview, explicit source selection and evidence-class summary. | Candidate is ready or held; ready remains separate from admitted. | None |
| Admit returned work | Adjacent pre-gesture notice naming the exact candidate and head change, with explicit acknowledgment. | “Admitted locally” only after the state transition succeeds; old → new head, immutable root, source count and unresolved foreign claims remain visible. | One lawful local advance |
| Rest / exit / discard staging | Visible statement of the effect on staging and any actual expiry. | Candidate can stay staged, or staging clears; prior admitted head remains. | None |

Child-legible primary language can stay short:

- **Check:** “Does this return match the Loom session you left?”
- **Challenge:** “What can this captured reply reveal?”
- **Admit:** “Add this checked return as Loom's next local work unit.”

Use exact technical distinctions under “Why held?” / “Inspect evidence” / “Inspect ancestry.” Do not label a receipt match “verified assistant,” “protected session,” “policy obeyed,” or “authenticated foreign history.” Local admission organizes a carried record and preserves the unresolved foreign edge.

## Pre-admission notice · required content

Place the notice next to the enabled Admit gesture, outside a collapsed inspector:

> Admit adds this exact task, answer and selected source commitments as the next local Loom work unit. The current head will change from [parent] to a new descendant. Root rules remain [root-policy reference]. Loom checked the carried record; the foreign assistant's internal use, memory and enforcement remain unobserved.

The pending candidate digest and expected current head must bind the acknowledgment. Editing task, answer, receipt, source selection, capture declaration or challenge references invalidates readiness/acknowledgment and requires a fresh Check. A remembered checkbox cannot authorize a different candidate. Challenge completion must never auto-click or imply Admit. Any current-head change during async validation invalidates the notice and candidate.

If the implementation creates a separate v0.2 custody ledger, say “next admitted Loom work unit” and expose that head separately from legacy v0.1 preparation state. The current v0.1 preparation path already appends PREPARED work units; silently calling that value an admission-only head would teach a false causal story. Do not retrofit stronger semantics through labels alone.

## Veto criteria

Pedagogue withholds human-route acceptance when any of these remains:

1. Check, Challenge, opening or staging advances the admission-only head.
2. Admit remains enabled after input/head/policy drift or stale acknowledgment.
3. “Ready,” MATCH or bounded challenge success is presented as already admitted.
4. Consequence notice appears after the gesture, only in JSON, only offscreen, or only in hidden DOM.
5. HOLD hides the last admitted head, promotes the rejected answer, or routes the operator to a continuation that uses it.
6. Malformed input erases its local error region and reports only at the distant builder.
7. Source IDs are silently prefilled as intentional admission; supplied sources and receiver-declared used sources collapse into one field.
8. Withheld source material becomes an “absent” source with no retained distinction.
9. Work-unit parent and answer/content parent use one unlabeled predecessor coordinate.
10. Cue pause extends expiry, retries silently restart admission, or a stale recovered record is automatically promoted.
11. An admission or preparation result hides its browser-only/reload survival boundary.
12. A read-only check is renamed SEND merely to feed the current audit adapter.

## Focus, errors, recovery and bounded surfaces

- Inline Check/HOLD region must remain rendered on parse/schema failure and include “No admission; current head unchanged.” Use a polite live region for results and field-local error association for malformed input.
- Keep keyboard focus on the checking control or move it deliberately to a focusable result heading; avoid unpredictable jumps to the builder. Admission success should focus its new-head result. The visible result must fit within the active route before long technical details.
- Long tasks/answers and large allowed source sets need compact summaries with explicit inspection. Never truncate the actual bound task, answer or source commitments. Eight-source engine limits require visible validation before gesture.
- Disclosure toggle, checkbox/acknowledgment, Check, Admit, rest and exit must be keyboard reachable with a visible focus indicator. Focus testing must use the actual browser; JSDOM availability is insufficient.
- Reload may restore carried bytes only through an explicitly designed recovery contract. Until that exists, warn before leaving that this browser's candidate/local ledger requires a saved export. Rest/exit must remain available without coercing admission.
- Treat all restored candidates as unadmitted; recheck the current root/head/policy and exact evidence before enabling Admit. A restored admitted ledger requires its own replay/integrity checks and a source/custody ceiling; storage presence alone supplies no external-origin evidence.
- Expose candidate expiry only when the protocol actually defines it. Current v0.1 turn checking has no expiry field. Do not invent a deadline from cadence or apply a cue timer as custody law.
- Repeated admission produces a stable visible duplicate/HOLD or documented idempotent prior result; it must never create a second descendant. Show out-of-order/stale-anchor HOLD before suggesting continuation.

## Additive implementation handoff

`app/dome-world/holonomy-loom/reentry-workspace.js` and `.css` implement the recommended route as an additive drawer. The v0.2 ledger is labeled independently from the legacy seed preparation. The UI retains task registration, exact pasted-return boundaries, policy-review declaration, inline Check/HOLD, candidate-specific admission acknowledgment, fixed-root old/new-head consequence, real excursion deadline, rest preserving that deadline, pending-registration discard and review-only export.

The module owns no admission law: the engine issues immutable candidates and performs compare-and-swap. UI acknowledgment is tied to that issued candidate reference and erased after task/return/source/review/challenge changes. Exact returned-object interior bytes are extracted from the pasted array rather than reconstructed with `JSON.stringify`. String entries may carry their original captured text. None of this authenticates the foreign origin of pasted material.

Post-admission continuation has a distinct progressive disclosure: **carrier only**. It displays the preceding admitted answer, starts source checkboxes clear, permits only the latest turn's explicitly retained source bodies, prepares an inspectable read-only carrier and requires a separate Copy gesture. It registers no new turn. The primary registered-task route remains the path for another admission-eligible return. This separation prevents a copied carrier from masquerading as a registered excursion.

Integration contract:

```js
const ui = mountPortableLoomReentryWorkspace(container, {
  environment,
  onAdmission: (custodySnapshot, latestUnit) => {},
  onChallenge: (custodySnapshot, latestUnit) => {},
  getChallenge: () => null
});
await ui.setSession(liveSeedSession, seedPacket);
ui.setChallenge(capturedChallengeEvidence); // invalidates admission readiness
ui.getRecord(); // review-only exported record, no restoration authority
ui.clearSession(); // explicit new seed transition only
ui.dispose();
```

`setSession` must run when an explicitly established live seed changes, never after `onAdmission`. Ordinary builder edits must not silently destroy the retained local admitted ledger. Legacy one-hop/Marrowline seed controls must remain labeled as seed routes or held after the local head advances; an old seed export cannot impersonate the current admitted descendant.

`tests/portable-loom-reentry-workspace.test.mjs` exercises the real process-local engine in JSDOM. These are source/DOM contracts, not browser witnesses or human comprehension evidence. The existing shared gesture adapter's explicit re-entry input-class HOLD remains in force.
