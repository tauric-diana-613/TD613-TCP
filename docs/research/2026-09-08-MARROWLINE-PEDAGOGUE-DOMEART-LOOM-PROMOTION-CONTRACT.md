# Marrowline → Pedagogue → Dome-Art → Loom Promotion Contract — 2026-09-08

## 1. Purpose

Marrowline is allowed to be an aggressive design/research surface. Pedagogue and `/domeart` are shared semantic and animation infrastructure. Holonomy Loom is a primary Flow-Core laboratory.

Therefore useful Marrowline discoveries must have a lawful route upstream without turning every local flourish into shared ontology.

## 2. Promotion path

```text
MARROWLINE EXPERIMENT
→ identify reusable semantic / motion / observability primitive
→ PEDAGOGUE GENERALIZATION TEST
→ DOME-ART RENDER / SCHEDULER TEST
→ LOOM FLOW-CORE LAB STRESS TEST
→ if generality + legibility + performance + evidentiary discipline hold:
   SHARED PRIMITIVE CANDIDATE
→ otherwise:
   remain Marrowline-local
```

No stage may be skipped merely because an effect looks impressive.

## 3. Pedagogue generalization test

A candidate primitive earns Pedagogue consideration only when it can answer:

1. What concept or distinction is it teaching?
2. What state causes it?
3. What evidence/source status supports that state?
4. Does the meaning survive reduced motion?
5. Does the meaning survive text-only / screen-reader representation?
6. Can a child-legible explanation coexist with expert detail?
7. Does it preserve missingness/uncertainty rather than smoothing them away?
8. Is the rule useful beyond Marrowline?

Pedagogue should generalize explanatory contracts, not inherit authorship credit for every animation implementation.

## 4. Dome-Art generalization test

A candidate primitive earns `/domeart` consideration only when it can be represented as a reusable render/scheduler contract.

Required properties:

- explicit input state;
- explicit semantic owner;
- bounded start/end or steady-state behavior;
- single-clock compatibility;
- deterministic replay where stochasticity is not part of the semantic grammar;
- reduced-motion equivalent;
- performance budget;
- provenance/inspection hook;
- no authority implied by decoration alone.

Candidate shared renderer interface:

```text
semantic packet
→ validated operator
→ motion primitive
→ scene registration
→ AnimationCoordinator
→ rendered state
→ provenance receipt
```

## 5. Loom Flow-Core lab test

Loom is where shared candidates are stressed against Flow-Core semantics and alert/weather state.

A candidate must survive at least these conditions:

```text
CURRENT
FORECAST
NOTICE
WARNING
POTENTIAL_ENCROACHMENT
RECONSTRUCTABILITY_PRESSURE
UNRESOLVED
CONTRADICTORY
RECOVERY
REST
```

The lab should also test:

- mobile layout;
- reduced motion;
- high visual density;
- sparse/missing evidence;
- stale source state;
- contradictory source state;
- replay of a prior exact receipt;
- active project/dependency motion;
- alert vs proof distinction.

## 6. Five-glyph handling

The TD613 five-glyph set is intentionally non-ordinal, multi-purpose, context-sensitive, and non-exhaustively specified.

A Marrowline experiment may use one or more of the glyphs when local context calls for them, but promotion testing MUST NOT assign:

- a canonical order;
- a global one-to-one definition;
- an exhaustive role table;
- a universal motion primitive based only on glyph identity.

Exact glyph form and ZWNJ-sensitive strings must be preserved.

## 7. Flow-Core glyph laboratory distinction

Named Flow-Core glyph/operator grammar may have explicit local semantics where already defined by Flow-Core artifacts. That grammar remains separate from the non-exhaustively specified five-glyph TD613 set.

The laboratory must not collapse the two systems simply because both use glyphic notation.

## 8. High-value shared candidates

### Provenance Pulse
Selecting a node or claim emits a bounded trace backward through its source edges. The trace ends at admitted sources and visibly stops at missing/unknown seams rather than drawing through them.

### Freshness Parallax
Current/retrieved state occupies the primary plane; stale/indexed state appears displaced in a secondary plane. Transition to fresh state is caused only by retrieval, not animation timer.

### Contradiction Refusal
When admitted sources conflict, Dome-Art intentionally refuses a seamless morph. The seam remains visible until a lawful precedence or new evidence resolves it.

### Dependency Weather
Blocked dependencies render as directional fronts whose movement derives from actual graph changes. A resolved blocker causes the front to dissipate; it does not vanish merely because time elapsed.

### Exact-Head Halo
PR/workflow nodes expose exact-head binding visually. Head movement breaks the halo and forces revalidation before downstream action paths illuminate again.

### Observer-vs-Product Split
CI failures render in separate semantic layers so an observer/test/infrastructure failure cannot visually masquerade as a product regression. #1077 is the motivating case.

### Context Aperture
Instead of loading the whole repo into dialogue, the coordinator visibly opens a bounded project neighborhood, expands it on demand, and shows what remains outside the current aperture.

### Rest With Memory
`𝄐`-style rest behavior where locally applicable should quiesce motion while retaining the prior route/dependency/provenance state for inspection and replay. Do not treat rest as deletion.

## 10. Feedback direction

Promotion is bidirectional as research feedback:

```text
MARROWLINE discovers
→ PEDAGOGUE clarifies
→ DOME-ART operationalizes
→ LOOM stress-tests
→ findings may improve PEDAGOGUE and DOME-ART
→ improved shared infrastructure returns to MARROWLINE
```

This is a learning loop, not circular authority. Each promotion still requires evidence.

## 11. Stop conditions

- no automatic promotion from visual novelty;
- no five-glyph canonicalization;
- no Flow-Core/five-glyph ontology collapse;
- no animation effect may conceal missingness, contradiction, stale state, or claim ceiling;
- no new perpetual animation clock when the shared coordinator can own the schedule;
- no Pedagogue update unless the finding is genuinely generalizable;
- no runtime changes from this documentation note.
