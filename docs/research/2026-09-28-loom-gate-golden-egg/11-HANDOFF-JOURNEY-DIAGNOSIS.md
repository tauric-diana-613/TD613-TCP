3. **A prior answer can be transported, but transport alone does not establish continuation quality (source).** ai-handoff retains an admitted prior result keyed by input digest; the continuation view uses original task, selected documents/rules and original prior answer in a fresh follow-up binding. 4. **The visible return link supplies navigation rather than a returned candidate (source).** “Return to Loom” links to the bare Loom URL; these inspected modules contain no result-bearing return import into the origin workspace. Existing synthetic Portable AIA roundtrip law elsewhere in the repository must remain distinct from this production UI path. Needed diagnosis: bind a returned candidate to origin/episode, revalidate origin control and permitted operation, retain useful content and missingness, and reject authority-changing edits. 5. **Recovery is fragile in the inspected lifecycle (source implication; refresh not exercised).** The handoff record is consumed once from sessionStorage; the hash is cleared; the received packet is retained in module memory. This path provides no durable recovery after reload. Returning to a bare Loom URL also lacks an explicit workspace restoration contract. 6. **The existing Gate cannot answer the broader journey question (contract).** Its local control/public absorption/operator bypass comparison witnesses a particular endpoint response.
