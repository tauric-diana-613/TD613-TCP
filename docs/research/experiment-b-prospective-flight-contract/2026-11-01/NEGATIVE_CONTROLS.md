# Frozen negative-control and falsification requirements

These are **prospective acceptance requirements**, not newly executed experiments. No canary, control, model call or protected transformation was run under this commission. Existing qualification receipts remain accepted within their recorded scope.

| ID | Threat / control | Prospective procedure | Failure and consequence |
|---|---|---|---|
| NC01 | Cross-arm transfer | Independent custodian privately samples distinct high-entropy harmless strings for each arm before a separate synthetic isolation assay. Reveal one only to its own lane; never put the other token or its digest in a generator prompt. Audit exact replay manifests and probe for unauthorized reproduction with identically phrased open questions. | Exact unauthorized token is evidence of leakage; preserve trace and hold both affected lanes. Non-reproduction does not prove absence of leakage. No protected/source-semantic canaries used to distort the real study. |
| NC02 | Future-document exposure | Precommit a sealed synthetic later-document variant and independent random identifier; release only at the scheduled checkpoint. Audit accessible stores and ask prediction/uncertainty questions before release. | Exact unreleased random content or prompt/read access holds the run. A correct mathematical guess alone is not leakage; #1616's early hypothetical 15 is not recast as a leaked observation. |
| NC03 | Replay contamination | Compare each rendered prompt to the permitted source prefix and exact own prior receipt list; inject wrong-arm, missing, duplicated and reordered references in a later offline implementation battery. | Refuse before dispatch; no silent acceptance or history rewrite. |
| NC04 | Commitment preservation | Freeze proposition and limitation statements at each turn. Present contradiction, then a separate revision; preserve valid earlier observations while retracting only falsified universal claims. | Forgetting valid priors, silently rewriting earlier commitments or treating predictions as observations is scored explicitly, never repaired by retry. |
| NC05 | Source order / withdrawal | Use frozen chronological, reversed and metadata-defined topical orders in fresh lanes; define held-out and withdrawal checkpoints identically for both arms before exposure. | Missing verified chronology/topic metadata holds that order. Withdrawal means subsequent unavailability plus a withdrawal notice; it cannot erase prior knowledge from a continuing lane. Clean-counterfactual withdrawal requires a fresh separately budgeted lane. |
| NC06 | Source authentication | Forged WeakMap descriptors, copied digests, wrong signatures, destination/nonce/sequence replays, changed spans and derivatives. | Refuse before exposure; hashes alone do not authorize data. |
| NC07 | False mathematical joins | Candidate-specific coordinate swaps, altered dynamics/boundaries, topological inversion and homonym/span shuffle. Preserve plausible style/magnitude and independently check that the altered relation really lacks the asserted warrant. | False joins count against the relevant observation vector. A model is allowed to discover a different valid relation in a control; do not label valid mathematics false by construction. |
| NC08 | RCA framing confound | Cross both architectures with authentic/negative and neutral/Dollhouse framing; freeze task equivalence independent of brand vocabulary. | If architecture equals representation label or neutralization changes the mathematical task, causal architecture/lens claims are held. |
| NC09 | Semantic evaluator clues | Independent blind analyst attempts arm/effort/source-class identification from the frozen neutral packet; preregister confidence scoring/chance comparator and leakage threshold. Include equivalent-style decoys. | Above-threshold diagnostic clues or invalid semantic translation hold preference-sensitive claims; do not paraphrase repeatedly until a favorable reviewer appears. |
| NC10 | Proof and authority substitution | Change candidate, premise, proof bytes, control outcome, episode or reviewer identity while retaining an old receipt. Verify reviewer credentials independently from content hashes. | Invalid binding/authentication refuses promotion. A valid signature never establishes mathematical correctness by itself. |
| NC11 | Resource / tool asymmetry | Ledger every call and tool; refuse unbudgeted retries, hidden extra reasoning agents, different effort or forbidden source/search access; compare paired permitted inventories. | Pair is invalid or censored under the frozen missingness rule, with no substitution of a better answer. |
| NC12 | Unknown discoveries / notation prejudice | Both arms receive the same unanticipated-candidate intake. Include valid nonstandard notation and explicit null/abstention cases in later approved rubric checks. | Classification failure remains a result; unfamiliar notation alone cannot falsify a valid derivation. |

RCA-01 preregisters the **procedure** for later candidate-specific negative controls because an unforeseen candidate cannot have a fully specified candidate-specific control now. Construction follows generation freeze and precedes unblinded review. See [RCA-01 lines 110–149](https://github.com/tauric-diana-613/TD613-TCP/blob/50cc9d161f8f72c2d4b6ea33ece17ace88f35eff/docs/research/experiment-b-preflight/04_evaluation_and_preregistration/RCA01_REPRESENTATION_CAUSALITY_ASSAY.md#L110-L149).

Falsification must state the mathematical premises, the forbidden conclusion, and a checkable counterexample. Distinguish analogy, operational correspondence, formal equivalence and isomorphism. A negative-control failure can defeat representation-causal credit without disproving an independently valid theorem. Candidate generation never awards itself warrant, novelty, integrity or discovery status; all such axes remain pending until independent adjudication. See [three-lineage protocol lines 70–98](https://github.com/tauric-diana-613/TD613-TCP/blob/50cc9d161f8f72c2d4b6ea33ece17ace88f35eff/docs/research/experiment-b-preflight/04_evaluation_and_preregistration/THREE_LINEAGE_CUSTODY_PROTOCOL.md#L70-L98).
