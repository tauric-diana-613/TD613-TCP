# Pedagogue Lineage Second Pass

Status: **RESEARCH-SIDE / QUESTION ROUTING ONLY / HUMAN-GATED**

Pedagogue’s Lineage Spine originally let an operator select provenance lenses explicitly. The second pass makes that ancestry operational in a narrower and safer way: already-compiled system diagnostics may activate the inherited questions that are relevant to the observed route.

```text
machine-level diagnostic
→ typed system deficit
→ provenance lens activation
→ inherited question
→ human review
```

This is not a thinker vote, a diagnosis of a person, or a redesign engine.

## Why this exists

Without a second pass, Pedagogue can carry Montessori, Malaguzzi, Miller, Laing, Graeber, Steiner, Dewey, Jacobs, A:shiwi-routed spatial knowledge, and the wider Flow-Core/Dome-World spine while still depending on an operator to remember which lens to select after every machine result.

The second pass allows existing receipts to call the relevant question family back into view. For example:

- `ADVISORY_WITHOUT_ROUTE` can activate Prepared Environment and Legibility Without Expert Monopoly;
- `PREMATURE_NAMING` can activate Rhythm and Cadence, Epistemic Refraction, and Third Teacher / Documentation;
- `REST_WITHHELD` can activate Temporal Sovereignty and Relational Safety;
- institutional action before registration can activate Institutional Time, Temporal Sovereignty, and Interpretive Labor;
- explicit many-to-one compression can activate Dromological Compression;
- a declared unresolved context before person attribution can activate Anti-Pathologization without claiming anything about the person;
- a declared community-segregation condition can activate Community Embeddedness without generalizing an Indigenous source tradition.

## Inputs

The second pass may consume:

- a Pedagogue interface diagnosis;
- an Institutional Time audit;
- a dromological sequence/cadence audit;
- a route-burden comparison;
- a closed vocabulary of explicitly declared system-level signals.

The direct compiler checks schema identity but does not independently prove the authenticity of a supplied receipt. Its output therefore remains question-routing material only. The integrated Design Gate path is the intended compiled route.

## Output

Each activated lens carries:

```text
lens_id
question
provenance_nodes[]
activation_basis[]
```

The receipt also preserves dormant lenses so absence of activation remains visible.

`activation_count` is explicitly not a score. Convergence is not computed. More active lenses do not imply a worse system, a more important thinker, or a stronger truth claim.

## Closed declared-signal vocabulary

The initial declared system signals are:

```text
ENVIRONMENT_REQUIRES_EXTRA_COMMAND_FOR_LEGIBLE_ACTION
PROCESS_WITNESS_MISSING
TRANSFER_ROUTE_FRAGMENTED
CONTEXT_UNRESOLVED_BEFORE_PERSON_ATTRIBUTION
COMMUNITY_ROUTE_SEGREGATED
RELATIONAL_SAFETY_REDUCED_TO_CONTAINMENT
STATIC_CATEGORY_BLOCKS_RELEASE
ACCESS_INTERPRETATION_AUTHORITY_COLLAPSED
CONTAMINATED_SOURCE_ROUTE_REQUIRES_QUARANTINE
```

Unknown signals fail closed. The second pass may not invent a new lens route because “the vibes are off.”

## Claim ceiling

```text
lens activation != evidence that the thinker is correct
lens activation != proof of a design defect
lens activation != human diagnosis
lens activation != source authority
lens activation != convergence
schema label != independently verified receipt authenticity
question routing != redesign authority
```

The second pass may surface inherited questions. It may not apply changes, intervene, release, mutate production, score a person, infer a learner profile, or close the seam.
