## Trick 2 — semantic, witness, and actuator planes remain typed

Parent transferable relation:

```text
TYPED_CONTROL_PLANE_SEPARATION
```

Candidate design heuristic:

```text
SEMANTIC_WITNESS_ACTUATOR_PLANE_SEPARATION
```

Three bounded planes:

```text
S-PLANE
semantic / behavioral / representational control state

W-PLANE
fact-bearing witness state, source identity, freshness, provenance, claim ceiling

A-PLANE
runtime / receiver / actuator state, physical or process clock, irreversible consequence boundary
```

Hard crossings:

```text
W -> S requires a typed reference constructor
S -> W produces a claim candidate, not a fact
S -> A requires a receiver / actuator contract
A -> W requires measurement custody
```

This is a design heuristic candidate. It does not assert that every AI architecture requires exactly three implementation modules.
