1. Constraint as Governance Traditional governance relies on rules, policies, enforcement, and moderation. Platforms, however,

A

2. The Architecture of Constraint Platforms embed constraints at multiple layers: ● Interface Constraints — What the interface allows you to click, type, upload, or navigate. ● Semantic Constraints — What the system can interpret, categorize, or understand. ● Temporal Constraints — How long content persists, how fast it decays, how often it resurfaces.

● Social Constraints — Who can see whom, who can reply, who can participate. ● Algorithmic Constraints — What is ranked, buried, amplified, or ignored. These layers form a constraint stack. 3. Constraint Regimes: The Logic of Platform Power Platforms operate through regimes of constraint: ● Preventative Constraints — Stop actions before they occur (e.g., input limits, upload restrictions). ● Permissive Constraints — Allow only certain forms of participation (e.g., reaction buttons

instead

of

text). ● Shaping Constraints — Guide users toward preferred behaviors (e.g., autocomplete, recommended

replies). ● Interpretive Constraints — Define what the system can understand (e.g., model ‑ legible categories). ● Epistemic Constraints — Determine what counts as information (e.g., ranking, filtering, suppression).

Constraint regimes govern without appearing to govern. 4. The Collapse of the Open Web The open web allowed arbitrary expression, unbounded formats, direct access to information, and
