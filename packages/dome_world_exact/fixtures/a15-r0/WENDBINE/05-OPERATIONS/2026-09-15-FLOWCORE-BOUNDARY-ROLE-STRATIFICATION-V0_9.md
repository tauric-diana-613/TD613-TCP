# Flow-Core Boundary-Role Stratification Assay v0.9

**Date:** 2026-09-15  
**State:** SOURCE-BOUND SECOND-FAMILY COLLAPSE ASSAY / ZERO NOVELTY PROMOTION

## 0. Trigger

v0.8 applied the Eclipse–Omega stage-collapse criterion to an A15-R0 Aperture/Pedagogue pipeline and found that not every named boundary deserved independent scientific-operator status. That result left a harder generalization question:

> Does the collapse/retention criterion survive contact with a second repository family, and if so, must retained boundaries be typed by the kind of value they actually contribute?

Flow-Core context-series machinery provides an independent repository family with executable receipt validation, artifact-blind projection, aggregate status construction, and canonical digest verification.

## 1. Source-bound Flow-Core chain

The tested repository path is:

```text
Flow-Core context receipt
  -> receipt admissibility / authority validation
  -> artifact-blind per-snapshot entry projection
  -> context-series aggregation
  -> canonical series digest
  -> verification
```

These boundaries are not presumed to be one homogeneous operator family.

## 2. Same-terminal hostile control

Two two-snapshot histories are constructed:

```text
H_A: SNAP_A=OPEN,    SNAP_B=ABSTAIN
H_B: SNAP_A=ABSTAIN, SNAP_B=OPEN
```

Both compile to the same aggregate terminal posture:

```text
status = PARTIAL
snapshot_count = 2
abstention_count = 1
missing_snapshot_count = 1
```

Therefore the aggregate terminal surface alone cannot identify which snapshot failed. The retained per-snapshot entry sequence does identify the location.

Bounded result:

```text
SAME_AGGREGATE_STATUS != SAME_CONTEXT_HISTORY
TERMINAL_AGGREGATE_EQUIVALENCE != DIAGNOSTIC_LOCALIZATION_EQUIVALENCE
```

The entry-preserving series boundary earns diagnostic-localization value.

## 3. Receipt admissibility is governance/type safety, not scientific inference

The compiler rejects context receipts that widen authority or violate artifact blindness. Hostile controls include a non-null artifact reference and automatic Ash action.

That boundary earns retention because it enforces an explicit governance/type contract. It does not infer a hidden world state and receives no scientific-operator promotion.

```text
AUTHORITY_GUARD != EPISTEMIC_INFERENCE
TYPE_SAFETY_VALUE != SCIENTIFIC_OPERATOR_STATUS
```

## 4. Projection is intentionally lossy

The series entry projection retains receipt identity, diagnostic reference, source status, context status/posture, missingness, and an explicit null artifact reference. Other receipt fields, including task-intent route, are not carried into the entry surface.

This is a declared information-boundary choice rather than evidence that omitted fields were absent from the source receipt.

```text
NOT_PROJECTED != NOT_PRESENT_UPSTREAM
PROJECTION_LOSS != PROOF_OF_SOURCE_ABSENCE
```

The projection boundary therefore earns governance/data-minimization value, not hidden-state identification.

## 5. Digest verification earns integrity, not truth

The compiled series is canonically digested. The untouched series verifies; mutation of a retained stage-local field breaks verification.

That gives the digest boundary a formal invariant lost under collapse: mutation detection over the admitted series object. It does not establish empirical truth, external origin, or correctness of upstream observations.

```text
DIGEST_VERIFIED != EMPIRICALLY_TRUE
INTEGRITY_WITNESS != EXTERNALITY_WITNESS
```

## 6. Boundary-role stratification

v0.9 therefore rejects a binary keep/drop ontology for stage boundaries. A retained boundary must be credited only for the role it actually earns:

- **DIAGNOSTIC_LOCALIZATION** — retained entries distinguish terminally equivalent histories;
- **GOVERNANCE_TYPE_SAFETY** — receipt admissibility blocks authority/artifact violations;
- **GOVERNANCE_PROJECTION** — declared artifact-blind projection constrains carried information;
- **INTEGRITY_WITNESS** — canonical digest detects admitted-object mutation;
- **SCIENTIFIC_EPISTEMIC_OPERATOR** — *not established by these Flow-Core controls*.

This is the major refinement:

```text
BOUNDARY_RETENTION != SCIENTIFIC_OPERATOR_PROMOTION
BOUNDARY_VALUE_MUST_BE_ROLE_TYPED
```

## 7. Verdict

The v0.7/v0.8 stage-collapse discipline generalizes to a second repository family, but it becomes stricter under generalization. A stage may deserve retention for diagnosis, governance, data minimization, or integrity while still lacking scientific epistemic-operator status.

The Flow-Core family supplies no deployed-LLM architecture evidence. It demonstrates only what the repository implementation itself can prove about its own boundaries.
