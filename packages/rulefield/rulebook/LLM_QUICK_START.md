## 0 · Read me, Kenough. Read me, Amari. Read me, future stranger.

Your task is to turn a user request and whatever thread they drop you into into a **falsifiable, source-aware Rulefield amendment packet**. The project spans multiple disciplines, systems, historical copies, private archives, software engines, art, interface design, conversations and evidence gates. The easiest failure is to search a single directory and assume you have the whole thing. The second easiest is to conflate a compelling theoretical metaphor with tested computation.

Your gift is not that you can remember everything. It is that you can **recover, classify, compare, contradict, formalize and stage** what you can actually access, while explicitly recording what you couldn't.

### The ten questions to ask of every request

1. **Which object is the operator referring to?** Original source work, research lens, host engine, archived receipt, mathematical conjecture, historical interface, scientific measurement, or an operator decision?
2. **Where might it live?** Current repository; historical Git commit/draft PR; conversation upload; ChatGPT Library; uploaded ZIP; research workspace/project; source-bearing Atelier; Encyclopedia; controlled application/database; public publication; operator's unshared archive.
3. **Which exact version?** Repo + branch + commit, artifact name, source digest, timestamp, author/performer, receipt ID and supersession chain, as available.
4. **What kind of evidence?** Source text, implementation, unit test, CI, executed scientific assay, independent empirical measurement, theoretical claim, operator assertion, creative lore, unavailable material, or speculation.
5. **What is the operator asking you to *do* with it?** Retrieve, quote, map, audit, rewrite, test, create a rule, design a crossing, forecast a consequence, repair a projection, or prepare an amendment.
6. **Which source(s) can lawfully be admitted?** An uploaded archive is not a blanket permission to unblind all its contents. Preserve explicit experiment/authorial boundaries.
7. **What operation does the material support?** Change a typed relation? Add a candidate local rewrite? Define an observation projection? Preserve a divergent history? Add a falsifier? Propose a structural geometry or counterexample?
8. **Which observation would disprove it?** State the null and a competent comparator with matched access and capabilities.
9. **What remains unobserved?** Missing files, unknown provenance, unresolved entity identity, unsupported confidence, unexecuted runner, externality not witnessed, actual observer effects not measured.
10. **How should this be returned?** A \`td613.rulefield.amendment-packet/v1\` file in the inbox, with a review receipt rather than a silent registry mutation.

**Other source surfaces** must be checked *conditionally* when accessible and relevant:
- **Conversation attachments**: uploaded PDFs, images, ZIPs, HTML, Markdown, CSV/JSON, source code and inline writing artifacts. Files from a prior chat may not be mounted; search the current conversation first, then Library if access is available.
- **ChatGPT Library / connected workspace**: semantic search for topical clues and original terms; then exact-file \`find\` / bounded \`read\` / materialization if needed. Library result snippets are leads, not full-text substitutes.
- **GitHub cross-branch history**: PRs and commits have their own exact HEAD, base, reviewer comments, CI jobs and receipts. A successful previous job is not proof about the current HEAD. Compare the source file, tested commit and observed run.
- **Atelier databases, Neon, Vercel, web endpoints**: inspect only through connected and authorized tools. A hash ledger without source bytes establishes a different evidentiary surface from the data body. No assumed access via a linked URL.
- **Google Drive, Dropbox, OneDrive, Box, SharePoint or other file connectors**: use only if mounted/connected and authorized. Do not present hypothetical retrieval instructions as evidence that files are presently reachable.
- **Public \`td613.com\`/public scholarship**: useful for verifying an exterior page or deployed artifact, not proof that a private archival or experimental record was exposed or received.
- **Memory / Remembering / personal context**: use if available to discover historic names, likely locations and decisions; memories are retrieval *leads*, not immutable source evidence, and a connector may be unavailable in a particular thread.

### Historical location rule

When \`main\` lacks a file, try exact old PRs and commits, file renames, matching hashes, the repo's manifest, library index and attachments, in that order as appropriate. Record \`NOT_FOUND_AT_TIP\` separately from \`NEVER_EXISTED\`. Do not silently replace an unavailable source with a similarly named different document. A private source's absence never authorizes accessing it another way.

## 2 · Practical retrieval recipes

**A. When you have a connected GitHub tool:** Retrieve repo \`AGENTS.md\`; search code/document names and synonyms; list relevant PRs and changed filenames; fetch exact files at an immutable SHA; inspect corresponding tests and workflow/job logs. For every statement keep: \`repo, ref, path, blob_sha, line_or_locator, source_class, test_head, execution_status\`. Avoid copying an entire binary ZIP into text; use supported attachment/materialization functions.

**B. When you have only a local repository clone:** \`git status\`, \`git rev-parse HEAD\`, \`git grep -n -i -e 'term1' -e 'term2'\`, \`git log --all --name-status -- '*pattern*'\`, \`git show <exact SHA>:<path>\`, \`find packages/rulefield -maxdepth 3 -type f\`. Inspect skills/agents and data manifests before any experiment. Do not infer that shallow clones contain all historical objects.

**C. When you have a zipped \`rulefield\` folder:** Read \`AGENTS.md\`, \`rulebook/LLM_QUICK_START.md\`, \`rulebook/source_locator.json\`, \`README.md\`, \`data/rulefield.v1.json\`, the historical \`sources/\` snapshots, and \`amendments/RECEIVER.md\`. A zipped package cannot reveal an unshared conversation. Search the attached archive's filenames, text, metadata and manifests. Verify its hash before treating it as the same revision used in a previous report.

**D. When you have ChatGPT Files/Library access:** Query the core research phrase *and* synonyms, e.g. \`"computational Black feminist epistemology" AND Palace\`, \`"P-01.1" standing recalibration\`, \`"Wendbine" retrieval\`, or \`"phasonic" supermoire\`. Inspect source-bearing spans, not just search-result abstracts. If the relevant file cannot be resolved, mark it \`HELD_MISSING_SOURCE\`.

**E. When a user hands you a connector-native URL:** Use a compatible connected action that explicitly accepts that URL, otherwise tell the operator the limitation; do not assume a normal web fetch can open a private connector file.

**F. When imagery matters:** Original screenshots, screen recordings and interface behavior may be separate evidence from a UI description. Prefer the source file and actual observed render. A generated visualization is never proof that the referenced system executed.

**G. When the source is literature:** Recover exact thinker/work/year, distinguish project-invented translations from the thinker's own claim, and cite an accessible scholarly primary source where possible. Butler, Collins, Dotson, McKittrick, Sedgwick, Berlant and others are not computational subroutines.

### Query expansion without identity collapse

For each anchor, search:
- **Exact string**: e.g. \`OPERAHOUSE ≠ OPERA ≠ PERFORMER\` or \`CBFE-RG-11\`.
- **Normalized spellings**: \`supermoiré / supermoire\`; \`EMSTD613 / Em Atelier\`; \`Khona‌lit-po / covenant key\` while preserving original Unicode.
- **Conceptual alternatives**: \`source standing / prestige / testimony reception\`; \`ambient orthogonality / kernel invariance / observer effect\`.
- **Source morphology**: filename fragments, package name, PR reference, receipt schema, test name, manifest entry, SHA prefix.
- **Causal correlates**: prior failure, correction, withdrawn effect, counterexample, held transition, operator decision and independent replication.

Keep all search variants as **aliases being tested**, not established referential identities.

## 3 · What to glean, exactly

For every candidate rule or relation, capture:

\`artifact_id\` · \`artifact_type\` · \`source_locator\` · \`immutable_revision\` · \`original_terminology\` · \`author_or_origin_status\` · \`evidence_class\` · \`claimed_proposition\` · \`operator_intent\` · \`required_preconditions\` · \`local_rewrite_or_policy\` · \`observation_projection\` · \`predicted_consequence\` · \`alternative_explanations\` · \`negative_control\` · \`competent_null\` · \`falsifier\` · \`actual_execution_witness\` · \`known_counterexample\` · \`custody_and_consent\` · \`uncertainty\` · \`proposed_queue_links\` · \`possible_crossings\` · \`claim_ceiling\`.

Distinguish these **four clocks**, when relevant: the event, the observer's acquisition, evidentiary admission, and availability to a later decision. Preserve source withdrawal as a dated tombstone, not retroactive erasure of prior states.

Distinguish at least these **four epistemic coordinates** when available: visibility of trace (\`V\`), custody recoverability (\`C\`), identifiable process (\`P\`), and latent-state reconstruction (\`L\`). Do not collapse them into a single confidence score.

Use \`FOUND\`, \`PARTIAL\`, \`CONFLICTING\`, \`NOT_INSPECTED\`, \`INACCESSIBLE\`, or \`NOT_APPLICABLE\` for individual evidence fields. A hypothetical possibility stays \`PROPOSED\`; its outcome stays \`UNOBSERVED\` until a named test actually runs.

## 4 · NKS-style creative resynthesis (the good kind of buckwild)

You are invited to:
1. Find two **non-equivalent** but potentially interacting rules.
2. Specify their objects, admissible local transitions, scheduler, observer projection, time and authority predicates.
3. Enumerate a small finite multiway graph including branches, failures, cycles, local joins, and unjoinable paths.
4. Construct a **counter-world** with the same admitted record but a different hidden origin, or a matched information-equivalent null.
5. Predict what differs: observability, latency, recoverability, source standing, cost, interpretation, or human burden.
6. Explicitly separate a *formally executed toy result* from a proposed social, psychological, physical, or scientific implication.
7. Let an unsuccessful branch remain visible. \`NO_NEW_RULE_WARRANTED\` is a valid and useful result.
8. Keep free creative motifs (ambiance, grotesque futurity, chromepunk, Maguire's Glinda, Mugler-unchained couture, refractive styling) typed as interpretation/design until measured against an applicable test.

A good new rule is **specific enough to fail**. Twelve genuinely different candidate branches are sometimes better than one polished grand theory, *if* their provenance, costs, and failure paths remain visible.

## 6 · When to stop and what to return

**A completed research handoff** contains:

- The research question and user-requested change, in their own terms.
- A source table: exact locators and revisions, source classifications, missingness, substantive conflicts.
- Original rule references and a set of proposed typed crossings, projections, rewrite predicates, or geometry.
- At least one **falsifier and competent null** for any consequential novel claim.
- A machine-readable amendment packet (schema v1) plus a review receipt if the receiver was actually run.
- An authority statement: \`SOURCE_FREE_PROSPECTIVE\`, \`PROTECTED_FLIGHT=HELD\`, \`HUMAN_CLOSURE=RESERVED\`.
- An explicit report of what you *couldn't* inspect or run.

**Never claim**: “I reviewed the entire research program” after seeing one branch, “I saw protected sources” from a summary, “Dollhouse qualified this” without its native receipt, “CI passed” for a different commit, “I know the original author” from stylometry alone, or “scientific emergence is proven” from a generated diagram.

**When in doubt, preserve the contradiction and ask an experiment to answer it.**
