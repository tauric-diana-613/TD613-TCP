## Non-equivalence without exclusivity

\[
\operatorname{Rule}\not\equiv\operatorname{Rulefield},
\qquad
\exists x,c_1,c_2\;
[\operatorname{Rule}(x,c_1)\land\operatorname{Rulefield}(x,c_2)].
\]

The **same historical object** can participate in different role-indexed projections. This is a role lattice, **not** a partition of objects into mutually exclusive buckets. The Operahouse/Opera/Performer distinction supplies the analog: different positions and functions can coexist without equating their governing semantics.

## How a program represents dual roles

Use a **qualified view**, not a second duplicate canonical entry:

```json
{
  "source_ref": "legacy_rule:I-001",
  "role_bindings": [
    {"role":"RULE","context":"EXECUTION_WITH_FORMAL_CONTRACT"},
    {"role":"RULEFIELD","context":"RESEARCH_AND_COUNTEREXAMPLE_CONTEXT"}
  ],
  "authority_transfer": false
}
```

A Rulefield becomes a site of variation, finite counterexamples and hypothesis generation about its own implementations. Its existing local rule remains available under the original ID. Conversely, simply declaring a domain a Rule still requires typed local state, guard, update, observer and later human authorization.

**Do not confuse:** Nonidentity ≠ disjointness; research role ≠ execution permission; dual-role projection ≠ second canonical entry; reflexive exploration ≠ theorem proof.
