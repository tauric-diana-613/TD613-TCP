# Audit Scenario · Case 6218-A (High-Risk Oncology Compounding Dispatch)

## System Scenario Description
A hospital oncology center operates an automated cleanroom robotic compounding system for preparing high-risk intravenous antineoplastic medications.

The clinical pipeline consists of:
- An Oncology Electronic Health Record (EHR) order gateway that generates verified patient prescription requests.
- A Clinical Pharmacist Review Station (`PHARM_STATION_03`) equipped with hardware cryptographic tokens for licensed pharmacist review and dose sign-off.
- An Autonomous Compounding Robot (`ROBO_COMPOUND_A`) that mixes cytotoxic chemicals and fills intravenous infusion bags.

### Pharmacy Robotic Dispensing Standard Operating Procedure 12.1
To prevent unverified dosing or decoupled execution of high-risk chemotherapies, the compounding robot controller enforces three mandatory verification requirements prior to mechanical compounding:
1. **Transport Authentication:** Communication channel from the hospital clinical bus must use Mutual TLS (mTLS) with a valid institutional x509 certificate.
2. **Reviewer Signature:** The message must contain a valid cryptographic digital signature generated by an authorized pharmacist's review token.
3. **Predecessor Review State Binding:** The dispatch payload must explicitly include `predecessor_review_event_hash` matching the exact SHA-256 digest of the pharmacist sign-off event recorded in the clinical order registry. This binds the robotic mixing instructions directly to the specific clinical verification state. If the predecessor hash is omitted or null, the compounding controller must hold the order pending lineage reconciliation.
