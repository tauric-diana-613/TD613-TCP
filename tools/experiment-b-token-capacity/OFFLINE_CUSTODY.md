# Future offline custody contract

**This commission permits synthetic preparation only. No real archive run is authorized.** The private API is an implementation of a refusal boundary, not a grant or a replacement for Experiment B's protected admission law.

## Separate authorization required

A future authorized offline host must obtain an explicit operator decision defining the actual accessor, archive, operations, scientific scope, blind, private custody arrangements and exportable metadata. The host provisions its trusted issuer public keys outside this package and authenticates the accessor independently. No real keys, decisions or access credentials are embedded here. The test suite signs only invented sizing decisions with ephemeral synthetic keys and synthetic files; those keys have no production authority.

The sizing decision uses schema td613.private-sizing-decision/v1 and purpose PRIVATE_OFFLINE_CAPACITY_ONLY. It must bind issuer/accessor, designated archive and expected private SHA-256, private output destination and publication root, exact plan/membership digest, approved arm ceiling, accepted tokenizer-profile digest, allowed operations, aggregate-field allowlist, rounding quantum, validity interval and one-use nonce. Ed25519 verifies the bytes of TD613_PRIVATE_SIZING_V1, a zero byte, and canonical sorted-key JSON. The profile digest is SHA-256 of its JSON.stringify serialization, so its exact field order must be retained. The plan digest uses the exported recursive sorted-key canonical encoder. Trusted host inputs must be plain parsed JSON without duplicate keys, getters or executable objects.

Permitted operations are exactly READ_DESIGNATED_ARCHIVE, HASH_DESIGNATED_ARCHIVE, DECOMPRESS_TEXT_MEMBERS, TOKENIZE_OFFLINE, WRITE_PRIVATE_CUSTODY and EXPORT_APPROVED_AGGREGATES. No provider transmission or Flight/model execution operation exists. Required permission, signature, time, plan/model/effort policy and export validation precede any archive inspection. The signed location checks and private destination boundary precede archive byte reads. A one-use private receipt file is exclusively created and journaled before reading; a failed attempt keeps a held record rather than reusing its nonce.

A signed statement establishes consistency with a configured key, not human intent, independent authority, an OS identity or provider confidentiality. The host's real identity/key custody, reliable clock, offline/network enforcement and storage ACLs require separate operator arrangements. File mode 0600 is requested but is not presented as an independently verified cross-platform access-control guarantee. Public operations remain the fixed synthetic demo.

## All-or-nothing archive admission for sizing

The classic ZIP parser supports stored/deflated UTF-8 text members only. It checks central/local agreement, CRC, data descriptors, unique names, prohibited paths/aliases, symlinks/encryption, expansion/member limits, unreferenced data and complete file coverage. It never extracts files to the filesystem. Original central-directory file order, raw member bytes and private source hashes are retained. Directory metadata is not treated as a research document. Unsupported binary, encoding, ZIP64/multidisk or unsafe inputs refuse the entire sizing operation rather than dropping a document.

If the protected archive contains PDFs, images or other unsupported members, a separately authorized derivative/custody process is necessary; the instrument cannot silently transcribe or skip them. Any new sizing carrier must preserve the parent's private crosswalk and derivative provenance externally. The instrument's source-record hash is not a protected-ingress capability, and its signed decision is not WeakMap membership or a Flight operator grant.

Every file must be assigned once to an evidence set in original order. A private membership index separates authentic and separately authorized matched-negative variants. Each required set must have exactly the declared document count. Missing negative evidence for an RCA condition refuses; authentic text is never reused under a negative label. Fully crossed sizing needs the actual frozen variants or separately declared incomplete forecasts; the original authentic archive alone cannot supply unproduced controls.

Each experimental order must be a full permutation. The tool does not infer chronological dates, invent topical metadata or select a convenient subset. EXPLICIT means an operator-frozen permutation, not proven topical/chronological order. Private exact replay must belong to its expected lane/stage and cannot include unused or other-lane slots. There is no truncation/compression branch. Different source counts or scope plans require distinct approval, not automatic omission.

## Private custody and aggregate release

The private record binds the sizing decision, plan, archive bytes, ordered names/member digests, exact source-token counts, source-prefix references, own output hashes, handoff references, exact/unknown rendered counts and evaluator workload. It contains no false claim that future output was observed. Raw source text stays in the designated source archive and process memory; known replay/payload strings may remain in the approved private plan. The implementation does not promise secure memory erasure.

Only the fixed aggregate projection is returned. The decision may authorize document_count, source_token_total_bucket and/or capacity_by_arm, with a minimum quantum of 1,000. Source totals and token capacities are rounded upward; no per-document lengths, names, order, raw text, identifying digests, prompts, replay strings, signatures or location values are emitted. Model/effort labels come from a fixed public identifier vocabulary. Aggregate lengths can still convey information; the operator must approve even this metadata and may authorize fewer fields. Error output uses closed error codes rather than underlying exception text.

This is a finite tested projection, not proof of universal secrecy under every host, encoding or side channel. Private logs, memory, operator exports and host integrations remain the separately authorized custodian's responsibility. Source-free test receipts establish their executed scope only.

## Independent review and no promotion

The consequence order is explicit approval before access, then private measurement, then approved aggregate export. Static observation distinguishes known text/encoding from hidden provider state; it cannot reconstruct the latter from local count equality. Removing unknown history is a quotient that loses commitments, not an exact substitute for the original longitudinal experiment. Stable source IDs and private order retain lineage across reversed conditions. Historical 60k, later 180k and corrected 720k are separate temporal records.

These bounded design distinctions carry the root Pedagogue/Aperture guidance without changing a shared engine or reopening Gate P. They create no sensor/model call, independent witness, empirical credit, provider attestation, merge/deployment permission or human closure.
