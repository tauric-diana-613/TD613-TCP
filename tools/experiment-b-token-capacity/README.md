## What is implemented

- Deterministic local BPE counting with pinned js-tiktoken 1.0.21. Both o200k_base and cl100k_base merge tables are reconstructed and checked against official OpenAI table hashes before use. Ordinary source text, including literal special-token strings, is encoded without normalizing Unicode or line endings.
- Frozen proposed renderers for baseline, both modular stages, both strong-union passes, synthesis, mathematical review, controls, warrant/novelty and semantic masking audit.
- Full sequential raw-evidence prefixes, exact own-history/handoff references, stable source identity across orders, and explicit unknown-output slots. Complete supplied replay is tokenized as one complete rendered JSON string; isolated component counts are not added and called exact.
- Separate observed-reference forecasts, hypothetical source-aware forecasts, imposed input/output budget envelopes, retry pools, all-conditions arithmetic and independent evaluator allocations.
- A future offline-custody API that requires an externally supplied signed sizing decision, approved accessor, exact plan, model/effort profile, designated archive, private output location, approved metadata fields, expiry and one-use nonce before archive inspection. No production trust roots, operator decisions or grants are included.
- An aggregate-only emitter. Exact member order, names, raw-byte hashes, token lengths and replay/call records remain in the private custody result. Public reports contain only authorized totals/buckets and arm-level capacity findings.

## Important exactness boundary

The retrieved official tokenizer registry does **not** map gpt-6.1-sol. This package therefore does not call an o200k reference count an exact GPT-6.1 Sol provider count. The synthetic demo intentionally reports MODEL MAPPING / HARD CONTROLS HELD. A future private run refuses an absent or unsigned model-tokenizer profile. An explicit operator-accepted mapping is an assumption, not an independent provider attestation. See [TOKENIZER_AND_MODELS.md](TOKENIZER_AND_MODELS.md).

Provider framing, hidden Codex harness inputs, future outputs/reasoning and unproduced controls/proofs cannot be exactly counted in advance here. The OpenAI counting endpoint is not called, and no source is transmitted. A nominally fitting envelope remains conditional on controls that this instrument cannot attest.

## Reproduce the synthetic work

From this repository subdirectory, with Node 22 or newer (match .node-version and runtime-profile.json for the recorded reference runtime):

1. Run npm ci --ignore-scripts --no-audit --no-fund. This installs only the pinned public tokenizer dependencies; do this before any separately authorized offline custody operation.
2. Run npm test. The runner uses real BPE encoders, synthetic ZIP files and ephemeral synthetic test keys; it performs no model inference.
3. Run npm run demo. This accepts **no archive argument** and uses only built-in invented documents.
4. Run node bin/synthetic-matrix.mjs for explicit synthetic alternative-scope/model/effort reports.
5. Run node bin/verify-package.mjs to check the committed artifact manifest and measured predecessor constants.

Actual test receipts and aggregate examples are under receipts/. Test keys and temporary synthetic custody files are not published. Imported predecessor files under sources/ retain their exact historical status; they are not executable reconstructed baseline checkouts.

## Future private operation is separate

There is no general-purpose archive command in the public demo. A separately commissioned trusted offline host may import runPrivateSizing from lib/private-custody.mjs only after the operator defines who may read the archive, exactly which operations are permitted, the intended blind, the approved plan/model profile, private custody arrangements and allowed exports. The host must provision real trust roots and authenticate the accessor independently; an accessor string or signature does not itself prove contemporaneous human authority. See [OFFLINE_CUSTODY.md](OFFLINE_CUSTODY.md).

All archive files must be accounted for. Unsupported binary, non-UTF-8, encrypted, ZIP64/multidisk, corrupt, oversized or unsafe inputs refuse the **entire** run. Missing matched negative variants are held rather than replaced with authentic text. No truncation, selective omission, automatic cap increase or silent scientific-scope change exists. Scope alternatives are explicit separate plans; the original study is not weakened by the instrument.
