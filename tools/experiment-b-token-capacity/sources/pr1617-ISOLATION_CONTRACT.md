## Roles and longitudinal state

The custodian controls source access, ordering and lineage but supplies no scientific answers. The broker renders approved prompts and dispatches only authorized work. Generators have no access to the other arm, future documents, custodian mappings, evaluator workspace, repository charters or operator conversation. Stage 2 uses a separate reviewer principal and workspace. Tawanna controls approval and unblinding. Amari adjudicates scientific adequacy without being replaced by an implementer receipt.

Each lane is keyed by study/episode, architecture, evidence class, representation, order, replication, model/effort block and stage. Start with an empty local history and no imported chat. Never reuse a prior lane's provider conversation or cache handle as its memory. Shared provider caching is not automatically semantic leakage; record it and do not claim independent isolation from distinct IDs. If the platform cannot isolate memories, skills, instructions, MCP servers and provider persistence as required, hold the lane.

Freeze a signed exposure schedule before generation: opaque source IDs, corpus-member digests in private custody, exact authorized sequence, metadata basis for chronology, order seed, control transforms, release index and allowed tools. Chronological labels require authenticated dates; admission order is not silently relabeled chronology. Topical ordering requires prospectively authorized metadata, not an executing generator's guesses.

At t0 record only the approved instructions and pre-exposure commitments. For document d, atomically journal authorization, prompt bytes/hash, consumed source/handoff digests, invocation, final messages, usage, tool events, commitments and failure status. The immutable commitment ledger contains exact model final statements plus references for proposition, assumptions, observations, prior dependencies, retraction/supersession, uncertainties and abstention. Structured indexing may point to the original text; it must not replace or silently summarize it.

Proposed 2A first jurisdiction receives the released raw-source prefix and all its own earlier two-stage outputs. The current second jurisdiction receives the actual first-jurisdiction handoff plus earlier handoffs and its own second-jurisdiction ledger; it receives no raw-source retrieval capability. Quotes/spans forwarded by the first jurisdiction remain attributed to that handoff. Final synthesis sees second-jurisdiction material, not a new raw-source bypass. This explicit feedback topology is a prospective change requiring approval.

Proposed 2B receives the same released raw-source prefix, all its own previous final messages, all common definitions and deterministic verification opportunities. Its first pass generates; its second may challenge, revise or abstain with the full context. It is never forced into a restrictive summary or denied the tools/negative-control channel afforded to 2A. Identical caps do not require discarding a valid comparator finding to match 2A output.

Each prompt construction receipt enumerates exact prior receipt IDs, source IDs/spans and handoff IDs; hashes the byte sequence; and excludes unreleased sources and other lanes. Both arms' source prefixes must agree at paired checkpoints. Replaying these bytes is **user-managed history replay**, not restoration of opaque provider reasoning state. Provider-resumed sessions are an unapproved alternative requiring a distinct state/compaction/cross-session policy and evidence.

If full replay exceeds any context or budget bound, stop the paired condition with the last valid checkpoint. No silent truncation, lossy summary, selective retraction removal or later-source preview is permitted. A proposed compression algorithm would be a new treatment requiring prospective review. An interrupted invocation with uncertain provider completion is recorded as uncertain, capacity-reserved and ineligible for favorable answer selection.

## Execution isolation and opportunity

Future workers require verified effective tool and memory inventories, minimal instructions, no inherited user/project chat, no general filesystem/network/search access, and separate arm-scoped private scratch. A broker may expose only pinned typed deterministic kernels with explicit input/result hashes, resource limits and identical service availability. Source retrieval is separately scoped; second-jurisdiction span verification must not return previously hidden text. Pin kernel versions and numerical tolerances. Kernel verification truth does not confer scientific authority. Existing source allowlists forbid several internal engine files as research evidence; a pure function service must not expose those files or their answer-bearing comments.

Call and token permits are atomically reserved before dispatch. All successful, failed, retried, cancelled-but-uncertain and hidden extra inference attempts must be accountable. If the native harness can make unobserved extra model calls or consumption cannot be bounded, strict opportunity parity is HELD. Same model/effort, output/input caps, call opportunities and permitted verification functions are necessary; equal hidden compute cannot be inferred from them.
